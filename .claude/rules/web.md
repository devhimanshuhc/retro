# Web rules (apps/web)

This Next.js (16.4) is newer than your training data: read `apps/web/node_modules/next/dist/docs/` before writing code. Full conventions are in the `web-ui` skill. Load it for any UI work.

## Folder plan
```
apps/web/                 # Next.js dashboard
├── AGENTS.md        # generated by Next.js: read bundled docs first (kept; `next dev` re-adds it)
├── CLAUDE.md        # imports AGENTS.md
├── .env.local / .env.example   # NEXT_PUBLIC_API_URL
├── next.config.ts
├── package.json
└── src/
    ├── app/         # (marketing)/page.tsx = landing at /; (app)/layout.tsx = sidebar shell; (app)/app/page.tsx = new run; (app)/runs/[id] = run thread
    ├── components/landing/  # landing sections; stack-art.json is generated by scripts/build-stack.mjs (Anatomy kit in vendor/anatomy), never hand-edited
    ├── components/  # UI components
    └── lib/         # api.ts (only place building API URLs), types.ts (mirrors pydantic models), pure logic + *.test.ts
```

## Conventions
- Live run data (status, events) renders in `"use client"` components fed by the WebSocket. Never `"use cache"` on run state; with `cacheComponents` on, uncached server fetches sit inside `<Suspense>`.
- `src/lib/api.ts` is the only place that builds API URLs. `src/lib/types.ts` mirrors the pydantic models (`add-endpoint` skill).
- Pure logic lives in `src/lib/` with `*.test.ts` (run by `node --test`; relative imports with `.ts` extension).
- Add deps with `npm install`, only when the browser/React/Next can't already do it.
